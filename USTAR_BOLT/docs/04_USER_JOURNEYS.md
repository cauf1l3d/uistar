# 04_USER_JOURNEYS — Ключевые пользовательские пути

## Сотрудник: «пришёл на смену, есть 15 минут»
1. Открывает USTAR на телефоне → Home отвечает: «Следующий шаг — проверка знаний, 12 минут».
2. Одна кнопка → quiz shell → результат → возврат на путь курса, открылся шаг 6.
3. Статус-полоса показывает: обязательное в срок, ступень 78%.
Критерий успеха: от входа до начала действия ≤ 2 касания.

## Сотрудник: «клиент спросил про зимнюю пену»
1. TopBar-поиск → «пены» → материал каталога (75 SKU).
2. Читает 2 минуты, отвечает клиенту. Материал помечен «Актуально» с владельцем.
Критерий: поиск → ответ ≤ 30 сек.

## Руководитель: утренний обход
1. Team dashboard: 2 просрочки, 1 риск адаптации, 2 готовы к аттестации.
2. «Напомнить» по просрочкам (1 клик), подтверждает практику наставничества Мурада, подаёт Патимат на аттестацию.
Критерий: все действия — с первого экрана, без отчётов.

## HR: закрыть дефицит контента
1. Обзор: «Складская логистика · ур. 3 — материалов нет, 8 человек заблокированы».
2. «Создать» → конструктор обучения → шаги из библиотеки + новая проверка.
3. Публикация → назначение через ступень → дефицит исчезает из обзора, у CEO зона риска гаснет.
Критерий: путь дефицит → публикация без выхода из HR Studio.

## CEO: месячный взгляд
1. Обзор: готовность 86%, обязательное 83% (цель 95%), 9 в резерве, риск — склад.
2. Drilldown склада: причина — дефицит контента, план до 1 сентября, ответственный HR.
Критерий: картина без единого LMS-термина; работает на планшете и проекторе.

## Admin: обновление Boost Union
1. USTAR MODE → TECHNICAL MODE (переход логируется).
2. Обновляет плагин; дизайн живёт в токенах/дочерней теме — регрессия минимальна (см. implementation/MOODLE_OVERRIDE_PLAN.md).

## Состояния (обязательные)
- Loading / Empty / Error — продемонстрированы в hr/content.html (переключатель демо-состояний).
- Locked learning — путь курса, шаги 6–7.
- Permission denied — паттерн: страница объясняет, к какой роли относится раздел, и даёт ссылку «на свою главную» (описан в 05_DESIGN_SYSTEM.md).
