## Ключевые выводы аудита текущего состояния

### Архитектурные
- **Кастомизация — конфигурационная, а не темная.** Нет дочерней темы: весь визуал — настройки Boost Union + Raw SCSS. Это патч-слой, а не система.
- **438 `!important` в 32 КБ Raw SCSS.** Стили воюют с каскадом Bootstrap/Boost вместо использования переменных. Любое обновление Moodle/Boost Union — риск визуальной регрессии.
- **Конфликты токенов:** `$body-bg: #161616` против форсированного `#141414`; `$body-color: #f0f0f0` против `#ECECEC`; `navbartint=#650AFA` (фиолетовый!) не из палитры и маскируется SCSS.
- **Шрифты объявлены, но не подключены.** Manrope/Montserrat указаны в правилах, ресурсов шрифтов нет — пользователи видят системный fallback.
- **Quiz/уведомления** — CSS компенсирует структуру DOM (z-index, pointer-events хаки) → помечено в OVERRIDE_MATRIX как FRAGILE.

### UX-выводы
- Текущий UI — «перекрашенный Moodle»: пользователь всё ещё мыслит категориями course/section/activity/gradebook.
- Нет ролевой модели интерфейса: сотрудник, руководитель, HR и CEO видят одну и ту же LMS-структуру.
- Нет сущностей продукта: навыков, ступеней, готовности, дефицита контента.
- Нет «одного следующего действия» — главная не отвечает на вопрос «что мне делать сейчас?».

## Решение, принятое на основании аудита

Целевой UI спроектирован «с чистого листа» (RULE 31: текущий Moodle — не visual reference), а перенос на Moodle спланирован по уровням OVERRIDE_MATRIX (см. `06_MOODLE_IMPLEMENTATION_MAP.md`): семантические токены → дочерняя тема → template/renderer overrides → `local_ustar` страницы. Патч-слой Raw SCSS подлежит поэтапному демонтажу.
